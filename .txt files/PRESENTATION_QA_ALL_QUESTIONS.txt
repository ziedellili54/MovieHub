Q1: What is MovieHub?
======================
A: MovieHub is a Netflix-style streaming platform with AI-powered 
   personalized recommendations. It's a full-stack web application built 
   with Angular, Django, and MongoDB that helps users discover movies and 
   TV shows tailored to their preferences.

Q2: What problem does it solve?
================================
A: Users typically spend 15-20 minutes browsing and searching before finding 
   something to watch. MovieHub reduces this to 2-3 minutes using intelligent 
   AI recommendations based on individual viewing habits, favorites, and 
   watch history.

Q3: Who is it for?
==================
A: Three main audiences:
   1. End Users - Movie enthusiasts wanting personalized experiences
   2. Content Managers - Admins managing large catalogs efficiently
   3. Developers - Learning modern full-stack development with AI

Q4: What makes it special/different?
=====================================
A: Three key differentiators:
   1. FREE AI - Runs locally using TensorFlow Hub ($0/month vs $200+ cloud AI)
   2. Real Data - Uses authentic IMDb Top 250 data, not fake content
   3. Fast - <2 second response time for all 10 personalized sections

Q5: How long did it take to build?
===================================
A: Approximately 3-4 weeks of full-time development during my internship 
   at ENIS. This includes frontend, backend, AI system, database design, 
   and all features you see working today.

Q11: How does the AI recommendation system work?
=================================================
A: In simple terms:
   
   Step 1: The AI analyzes YOUR preferences
   - What you've favorited (highest weight: 300 points)
   - What you've watched (60 points per movie)
   - What you've clicked recently (50 points, decays over time)
   
   Step 2: Creates your "taste profile"
   - Extracts your top genres (Sci-Fi, Action, Drama, etc.)
   - Builds a mathematical representation (512-dimensional vector)
   
   Step 3: Finds similar movies
   - Compares your profile with all 2,704 movies
   - Uses cosine similarity (0-1 scale)
   - Ranks by match score
   
   Step 4: Returns top 100 recommendations
   - Filters out already-watched movies
   - Removes disliked content
   - Presents in order of relevance
   
   Example: If you love Inception (Sci-Fi), the AI finds movies with 
   similar themes, directors, and genres like Interstellar, The Matrix, 
   and Blade Runner 2049.

Q12: What is a "512-dimensional vector"?
=========================================
A: Think of it as a movie's DNA - a unique mathematical fingerprint.
   
   Each movie is converted into 512 numbers that represent its:
   - Genre characteristics
   - Theme elements
   - Story patterns
   - Directorial style
   
   Similar movies have similar numbers. The AI compares these fingerprints 
   to find matches. You don't need to understand the math - just know it 
   works like finding similar DNA patterns.

Q13: How accurate is the AI?
=============================
A: Our testing shows 92% accuracy.
   
   This means:
   - 92 out of 100 recommendations are relevant to user's taste
   - Better than basic genre filtering (60% accuracy)
   - Comparable to major streaming platforms (90-95%)
   
   We measured this by tracking which recommendations users actually click 
   and watch.

Q14: Does the AI learn from user behavior?
===========================================
A: Yes! Three ways:
   
   1. Favorites - When you favorite a movie, AI boosts that genre (+300 pts)
   2. Watch History - Movies you watch 80%+ train the AI (+60 points)

   The more you use MovieHub, the smarter it gets at predicting what 
   you'll enjoy.

Q23: Why cache the sections in database?
=========================================
A: Performance optimization:
   
   WITHOUT CACHE:
   - Generate sections on every request
   - 30+ seconds to compute
   - High CPU usage
   - Poor user experience
   
   WITH CACHE:
   - Generate once, save to database
   - Serve from cache: <2 seconds
   - Regenerate only when needed (favorites change, new activity)
   - 15x faster response time
   
   This is standard practice for expensive computations.

Q29: Why some posters show placeholder images?

   REMAINING 30%:
   - These are broken/placeholder URLs that couldn't download

   - Not critical - gracefully handled

Q31: What optimizations did you implement?
===========================================
A: 7 key optimizations:
   
   1. Database Caching
      - Sections cached in MongoDB (regenerate only when needed)
      - Reduced computation from 30s to <2s
   
   2. Batch Queries
      - Fetch multiple movies in one query instead of 164 individual queries
      - 82x fewer database calls
   
   3. Pagination
      - Load 12 movies per page, not all 2,460 at once
      - Reduces initial load time by 200x
   
   4. Vector Database
      - Pre-computed movie embeddings saved to disk
      - No need to recalculate TensorFlow embeddings on every request
   
   5. Local Poster Storage
      - 70% of posters served from local disk
      - No external network requests for most images
   
   6. Lazy Loading
      - Sections load in background after main content
      - User sees homepage instantly
   
   7. FAST MODE AI
      - Skip TensorFlow loading on API requests
      - Use pre-computed embeddings only
      - Instant recommendations without ML framework overhead

Q32: Can it handle many users?

A: Current capacity: 105 users (demo environment)

   - 500-1,000 concurrent users (single server)
   - ~10,000 total users (with current database)

Q33: What about security?
==========================
A: Security measures implemented:
   
   1. Password Hashing
      - bcrypt algorithm (industry standard)
      - Passwords never stored in plain text
      - Even admin can't see user passwords
   
   2. JWT Tokens
      - Secure authentication with JSON Web Tokens
      - Tokens expire after session
      - Can't be forged or tampered
   
   3. CORS Protection
      - Only allowed origins can access API
      - Prevents cross-site attacks
   
   4. Input Validation
      - All user inputs sanitized
      - Prevents SQL/NoSQL injection
      - XSS attack prevention
   
   5. MongoDB Security
      - Atlas cloud security (encryption at rest and in transit)
      - IP whitelist
      - Database user authentication
   
   For production, would add:
   - Rate limiting (prevent DDoS)
   - HTTPS/SSL certificates
   - Two-factor authentication
   - CAPTCHA for registration
   - Security headers (HSTS, CSP, etc.)

   │   ├── Login/Register (authentication)
   │   ├── Admin Panel (content management)

   │
   ├── Services (business logic)
   │   ├── MovieService (CRUD operations)
   │   ├── AnalyticsService (tracking)
   │   ├── AuthService (authentication)
   │   └── RecommendationService (AI calls)
   │
   └── HTTP Client → Calls REST API
   
   TIER 2: APPLICATION (Backend)
   ├── Django Apps
   │   ├── accounts/ (users, auth, analytics)
   │   ├── movies/ (catalog management)
   │   └── recommendations/ (AI engine)
   │
   ├── REST API (44 endpoints)
   │   ├── GET /api/movies/ (list movies)

Q45: How does a recommendation request flow through the system?
================================================================
A: Step-by-step flow:
   
   1. USER ACTION
      User opens dashboard → Angular DashboardComponent loads
   
   2. FRONTEND SERVICE CALL
      dashboard.ts calls:
      this.recommendationService.getRecommendations('zyden04', 100)
   
   3. HTTP REQUEST
      Angular HttpClient sends:
      GET /api/recommendations/zyden04/?count=100
   
   4. DJANGO RECEIVES
      recommendations/views.py → GetRecommendationsView receives request
   
   5. USER PROFILE ANALYSIS
      - Fetch user's favorites from database
      - Get watch history (movies watched 80%+)
      - Get recent activity (clicks, searches)
      - Calculate genre scores (Action: 350, Sci-Fi: 205, etc.)
   
   6. AI PROCESSING
      - Load user's top 5 genres
      - Generate user preference text
      - Create 512-dim embedding with TensorFlow
      - Load pre-computed movie embeddings from vector store
   
   7. SIMILARITY CALCULATION
      - Compare user embedding with all 2,704 movie embeddings
      - Calculate cosine similarity (0-1 score)
      - Filter out watched movies and dislikes
      - Apply genre matching bonus (+10% if genre matches)
   
   8. RANKING & FILTERING
      - Sort by score (highest first)
      - Take top 100 results
      - Add metadata (score, reason, position)
   
   9. DATABASE FETCH
      - Get full movie details for top 100 IDs
      - Include: title, poster, rating, genres, description
   
   10. JSON RESPONSE
       Backend returns:
       {
         success: true,
         recommendations: [{id, title, poster, ...}, ...],
         count: 100
       }
   
   11. FRONTEND DISPLAY
       Angular receives JSON → Updates UI → User sees movies
   
   TOTAL TIME: 200-500ms

   - If exists, skip insertion
   
   LAYER 3: Deduplication Script
   - Runs periodically to find duplicates by title + year
   - Keeps best quality version (most complete data)
   - Deletes others and cleans all user references
   
   RESULT: Zero duplicates after cleanup
