✅ CONCEPTS FONDAMENTAUX:

1. NoSQL vs SQL
   - Documents JSON vs Tables relationnelles
   - Schéma flexible vs Schéma rigide
   - Scalabilité horizontale
   - Dénormalisation vs Normalisation
   - Cas d'usage (données non structurées, big data)

2. Structure MongoDB
   - Database: Conteneur de collections
   - Collection: Groupe de documents (≈ table SQL)
   - Document: Enregistrement JSON (≈ ligne SQL)
   - Field: Attribut du document (≈ colonne SQL)

3. CRUD Operations
   - Create: insert(), insertOne(), insertMany()
   - Read: find(), findOne(), aggregate()
   - Update: update(), updateOne(), updateMany()
   - Delete: delete(), deleteOne(), deleteMany()

4. Indexation
   - Index sur champs fréquemment requêtés
   - Index composés (plusieurs champs)
   - Index texte pour recherche full-text
   - Impact sur performance (lecture vs écriture)

✅ TECHNIQUES AVANCÉES APPRISES:

1. MongoEngine ODM
   - Définition de schémas avec classes Python

2. Requêtes Complexes
   - Filtres multiples (Q objects)
   - Tri (order_by)
   - Pagination (skip, limit)
   - Projection (only, exclude)
   - Recherche regex (case-insensitive)

3. Agrégation Pipeline
   - $match: Filtrage

4. Gestion de Relations
   - Embedded documents (sous-documents)

   - Cosine Similarity (similarité cosinus)
     → Mesure l'angle entre deux vecteurs
     → Score de 0 (différent) à 1 (identique)
     → Formule: cos(θ) = (A·B) / (||A|| ||B||)
   
   - Euclidean Distance (non utilisée mais connue)
     → Distance géométrique entre points
     → Plus petite = plus similaire

4. Feature Engineering
   - Extraction de caractéristiques pertinentes
   - Pondération des features (primary genre 3x, secondary 1x)
   - Normalisation des données
   - Création de profils utilisateurs

✅ ALGORITHMES IMPLÉMENTÉS:

1. Pondération des Genres (Genre Weighting)
```python
# AVANT (INCORRECT - remplacement):
genre_weights[genre] = weight  # ❌ Oublie les genres précédents

# APRÈS (CORRECT - accumulation):
genre_weights[genre] = genre_weights.get(genre, 0) + weight  # ✅
```

Résultat:
- Si user aime Drama (300) + Action (200) + Horror (150)
- Total Drama: 300, Action: 200, Horror: 150
- Recommandations mixent les 3 genres

2. Decay Exponentiel (Recent Activity Importance)
```python
for idx, activity in enumerate(activities[:30]):
    if idx < 5:
        weight = 50 - (idx * 5)      # 50, 45, 40, 35, 30
    elif idx < 10:
        weight = 30 - ((idx-5) * 5)  # 25, 20, 15, 10, 5
    else:
        weight = 5
```

Concept: Les actions récentes ont plus d'importance

3. Similarité Cosinus (Cosine Similarity)
```python
from sklearn.metrics.pairwise import cosine_similarity

# user_vector: [0.23, 0.45, 0.12, ..., 0.67]  (512 dims)
# movie_vector: [0.19, 0.48, 0.10, ..., 0.65] (512 dims)

similarity = cosine_similarity([user_vector], [movie_vector])[0][0]
# Résultat: 0.87 (87% similaire)

score_percentage = (1 - distance) * 100  # 0.87 → 87%
```

┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. ARCHITECTURE DE CACHE MULTI-NIVEAUX                                      │
└─────────────────────────────────────────────────────────────────────────────┘

✅ CONCEPT APPRIS: Système de cache à 3 niveaux

NIVEAU 1: Cache Base de Données (MongoDB)
- Collection: user_personalized_sections
- TTL: 24 heures
- Invalidation: Sur changement préférences utilisateur
- Avantage: Partagé entre serveurs, persistant

NIVEAU 2: Cache Vectoriel (Fichier)
- Fichier: vector_db/movies.pkl
- Chargé au démarrage du serveur
- Persistant sur disque
- Avantage: Pas de recalcul d'embeddings

NIVEAU 3: Cache Navigateur
- Cache HTTP du navigateur
- Headers Cache-Control
- Invalidation: Ctrl + F5 (hard refresh)

LEÇONS:
- Cache = Performance (3-5s → 500ms)
- Invalidation = Fraîcheur des données
- Multi-niveaux = Flexibilité et rapidité

┌─────────────────────────────────────────────────────────────────────────────┐
│ 2. INTÉGRATION MULTI-SOURCE D'APIS                                          │
└─────────────────────────────────────────────────────────────────────────────┘

✅ CONCEPT APPRIS: Stratégie de fallback API

IMPLÉMENTATION:
```python
def get_rating_multi_source(title, year):
    # Priorité 1: OMDB API (plus précis)
    rating = fetch_omdb(title, year)
    if rating: return rating
    
    # Priorité 2: TMDB API (backup gratuit)
    rating = fetch_tmdb(title, year)
    if rating: return rating
    
    # Priorité 3: Défaut intelligent
    rating = assign_default(title, year)
    return rating
```

STRATÉGIE:
1. Essayer source primaire (OMDB)
2. Si échec, essayer backup (TMDB)
3. Si échec, calculer défaut intelligent
4. Ne JAMAIS retourner None (100% couverture)

LEÇONS:
- Résilience: Ne jamais dépendre d'une seule API
- Defaults intelligents: Mieux qu'aucune donnée
- Fallback en cascade: Toujours avoir un plan B

┌─────────────────────────────────────────────────────────────────────────────┐
│ 5. DESIGN D'ALGORITHMES DE QUALITÉ (NETFLIX-STYLE)                          │
└─────────────────────────────────────────────────────────────────────────────┘

✅ CONCEPT APPRIS: Qualité avant tout

IMPLÉMENTATION:
```python
def sort_by_quality(movies, user_genres):
    def calculate_score(movie):
        # PRIMAIRE: Qualité (IMDB rating)
        quality_score = movie.imdb_rating * 10  # 9.5 = 95 points
        
        # SECONDAIRE: Match genre (+10% max)
        genre_bonus = 0
        if match_user_genres(movie, user_genres):
            genre_bonus = 10
        
        # TERTIAIRE: Récence (+5% max)
        recency_bonus = 0
        if movie.year >= 2020:
            recency_bonus = 5
        
        return quality_score + genre_bonus + recency_bonus
    
    return sorted(movies, key=calculate_score, reverse=True)
```

LEÇONS:
- Qualité (rating) = Critère principal (90%)
- Préférences utilisateur = Bonus secondaire (10%)
- Comme Netflix: Montrer le MEILLEUR, adapté à l'utilisateur

for i, movie in enumerate(movies):
