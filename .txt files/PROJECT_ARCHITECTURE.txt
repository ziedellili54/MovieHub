1. HIGH-LEVEL ARCHITECTURE
═══════════════════════════════════════════════════════════════════════════════

MovieHub is a Netflix-style streaming platform with AI-powered recommendations.
The application follows a client-server architecture with three main layers:

┌─────────────────────────────────────────────────────────────────────────────┐
│                            PRESENTATION LAYER                                │
│                     (Angular 18 Frontend - Port 4200)                        │
│                                                                               │
│  Components:                                                                  │
│  ├── Dashboard (Home, Browse, Search)                                        │
│  ├── Authentication (Login, Register)                                        │
│  ├── Admin Panel (Movie Management, User Management, Pack Builder)           │
│  └── Movie Detail Modal                                                       │
│                                                                               │
│  Services:                                                                    │
│  ├── MovieService (CRUD operations)                                          │
│  ├── AnalyticsService (User behavior tracking)                               │
│  ├── AuthService (Authentication)                                            │
│  └── RecommendationService (AI recommendations)                              │
└─────────────────────────────────────────────────────────────────────────────┘
                                    ↕ HTTP/REST API
┌─────────────────────────────────────────────────────────────────────────────┐
│                           APPLICATION LAYER                                  │
│                    (Django/Python Backend - Port 8000)                       │
│                                                                               │
│  Apps:                                                                        │
│  ├── accounts (Authentication, User Profiles, Analytics)                     │
│  ├── movies (Movie/TV Show Management, OMDB Integration)                     │

5. DATABASE SCHEMA (MongoDB)
═══════════════════════════════════════════════════════════════════════════════

DATABASE: netflix

COLLECTIONS:

1. movie
   Purpose: Store all movies in the catalog
   Schema:
   {
     _id: ObjectId,
     show_id: String (unique),
     title: String (indexed),
     type: String ("Movie"),
     director: String,
     cast: String,
     country: String,
     date_added: String,
     release_year: Integer,
     rating: String,
     duration: String,
     listed_in: String (genres, comma-separated),
     primary_category: String (main genre),
     description: String,
     poster: String (URL)
   }
   Indexes: title, type, release_year, listed_in

2. tvshow
   Purpose: Store all TV shows
   Schema: Same as movie but type = "TV Show"

3. user
   Purpose: Store user accounts
   Schema:
   {
     _id: ObjectId,
     username: String (unique),
     email: String,
     password: String (hashed),
     role: String ("user" or "admin"),
     created_at: DateTime
   }

4. favorite
   Purpose: Store user favorite movies
   Schema:
   {
     _id: ObjectId,
     username: String,
     movie_id: ObjectId (ref: movie/tvshow),
     added_at: DateTime
   }

5. user_pack
   Purpose: Store custom user collections
   Schema:
   {
     _id: ObjectId,
     username: String,
     name: String (pack name),
     level: Integer (1-10),
     genres: List[String],
     movies: List[ObjectId]
   }

6. user_activity
   Purpose: Track all user interactions
   Schema:
   {
     _id: ObjectId,
     username: String,
     movie_id: ObjectId,
     activity_type: String ("view", "search", "click", "favorite", "watch"),
     timestamp: DateTime,
     metadata: Object (additional data)
   }

7. movie_watch_history
   Purpose: Track watch progress per movie
   Schema:
   {
     _id: ObjectId,
     username: String,
     movie_id: ObjectId,
     movie_title: String,
     movie_type: String,
     watching_percentage: Float (0-100, user-editable),
     watch_percentage: Float (0-100, auto-calculated, deprecated),
     watch_duration_seconds: Integer,
     last_watched: DateTime,
     genres: List[String]
   }

8. user_preferences
   Purpose: Store AI learning data
   Schema:
   {
     _id: ObjectId,
     username: String,
     favorite_genres: List[String],
     favorite_types: List[String],
     last_updated: DateTime
   }

6. AI RECOMMENDATION SYSTEM
═══════════════════════════════════════════════════════════════════════════════

HOW AI WORKS:

The AI recommendation system uses content-based filtering with TensorFlow embeddings.

STEP-BY-STEP PROCESS:

1. MOVIE INDEXING
   ├── Extract movie metadata (genres, description, director, etc.)
   ├── Create rich text representation (emphasis on PRIMARY genre)
   ├── Generate 512-dimensional embedding using TensorFlow Hub USE v4
   └── Store embedding in vector database (movies.pkl)

2. USER PROFILE CREATION
   ├── Analyze user favorites (highest weight: 300 for primary, 100 for secondary)
   ├── Analyze recent activity (exponential decay: 50→5 based on recency)
   ├── Analyze watch history (medium weight: 60 for primary, 20 for secondary)
   ├── ✅ ACCUMULATE genre weights (Drama + Horror + Action all remembered)
   └── Create user preference text (genre-focused, NO titles)

3. RECOMMENDATION GENERATION
   ├── Generate embedding for user profile
   ├── Search vector DB for similar movies (cosine similarity)
   ├── Filter out already watched movies
   ├── Apply genre matching bonus (10% for matching genres)
   ├── Rank by similarity score (0-100%)
   └── Return top N recommendations

4. TRENDING ALGORITHM
   ├── Get most favorited movies across all users
   ├── Weight by recent activity (last 30 days)
   ├── Filter duplicates
   └── Return top N popular movies

KEY FEATURES:
├── Genre Accumulation (NOT replacement)
├── Per-movie watch time tracking
├── Real-time learning from user behavior
├── FREE (no API costs, runs locally)
├── Fast (50-100 movies/second)
└── Multilingual support

7. USER FLOWS
═══════════════════════════════════════════════════════════════════════════════

USER REGISTRATION & LOGIN:
1. User visits /register
2. Submits username, email, password
3. Backend creates User document in MongoDB
4. Redirects to /login
5. User logs in → receives session token
6. Redirects to /dashboard

BROWSING MOVIES:
1. User lands on dashboard
2. Frontend loads:
   ├── Featured movie (random from catalog)
   ├── Continue watching (from MovieWatchHistory)
   ├── AI Recommendations (from recommendation engine)
   ├── Trending (popular movies)
   └── Custom packs (user collections)
3. User scrolls through carousels (5 items per page)
4. Clicks movie → opens detail modal
5. Backend tracks view in UserActivity

WATCHING A MOVIE:
1. User clicks "Regarder" button
2. Frontend shows movie detail modal
3. User adjusts watching percentage (0-100%)
4. Frontend sends PUT /api/analytics/watching-percentage/
5. Backend updates MovieWatchHistory
6. Movie appears in Continue Watching section

AI RECOMMENDATIONS:
1. User performs activities (favorites, searches, views)
2. Backend tracks in UserActivity collection
3. When user opens dashboard:
   ├── Frontend calls GET /api/recommendations/{username}/
   ├── Backend creates user profile from all activities
   ├── AI generates embedding for user preferences
   ├── AI searches vector DB for similar movies
   ├── AI filters and ranks results
   └── Returns top 100 recommendations
4. Frontend displays in carousel

ADMIN OPERATIONS:
1. Admin clicks "Admin" button
2. Sidebar opens with:
   ├── Sync Netflix Data (fetch by year/type)
   ├── Add Custom Movie (manual entry or OMDB)
   ├── Search OMDb (bulk import)
   ├── User Management (view/delete users)
   └── Pack Builder (create themed collections)
3. Admin performs operation
4. Backend updates MongoDB
5. Frontend refreshes data
